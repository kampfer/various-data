# Spec Delta

## Purpose

让每次任务运行都可追溯、可手动触发，并在失败时主动通知维护者，从而不必再登录服务器翻查日志文件来判断任务是否正常。

## ADDED Requirements

### Requirement: 运行历史可查

每次任务触发 SHALL 保留本次运行的记录，至少包含开始时间、结束时间、退出状态与执行日志；记录 MUST 可按任务名与时间检索历史运行。

#### Scenario: 查看最近运行

- **WHEN** 维护者查询某个任务的历史运行
- **THEN** 系统按时间倒序列出该任务的历史运行及其退出状态

#### Scenario: 查看失败运行日志

- **WHEN** 某次运行以非零退出码结束
- **THEN** 维护者可查看该次运行的完整输出日志，用于定位失败原因

### Requirement: 手动触发

维护者 SHALL 能对任一已定义任务手动触发一次执行，且手动触发 MUST NOT 改变该任务既有的定时节奏。

#### Scenario: 手动补跑

- **WHEN** 维护者对每日任务手动触发一次执行
- **THEN** 立即产生一次新的运行记录，且该任务原有的每日定时触发保持不变

### Requirement: 控制台仅本机可访问

任务编排系统的 Web 控制台 MUST 仅监听 `127.0.0.1`，MUST NOT 对外网暴露；维护者通过 SSH 端口转发等方式访问。

#### Scenario: 外部主机尝试访问

- **WHEN** 从服务器以外的机器直接访问控制台端口
- **THEN** 连接被拒绝，无法建立会话

### Requirement: 失败邮件告警

任务运行失败时 SHALL 向维护者发送邮件告警；成功运行 MUST NOT 发送邮件。SMTP 账号与授权码 MUST NOT 出现在仓库任何文件中。

#### Scenario: 运行失败发送告警

- **WHEN** 某次运行以非零退出码结束
- **THEN** 维护者收到包含任务名、失败时间与运行标识的邮件

#### Scenario: 运行成功不打扰

- **WHEN** 某次运行以零退出码结束
- **THEN** 不发送任何邮件
