# Spec Delta

## Purpose

定义数据库备份的周期、文件命名、快照一致性与完整性自检，使每次备份都是可用的、可追溯的一致性副本。

## ADDED Requirements

### Requirement: 按周期执行数据库备份

系统 SHALL 在每月 1 日执行一次数据库备份；备份对象 MUST 由运行模式决定，生产备份生产库，开发备份开发库。

#### Scenario: 每月备份

- **WHEN** 到达每月 1 日的备份触发时间
- **THEN** 系统对当前运行模式对应的数据库执行一次备份

#### Scenario: 生产模式备份

- **WHEN** 以生产模式执行备份
- **THEN** 备份文件来源为 `data/various_data.db`

### Requirement: 备份文件命名与位置稳定

备份文件 MUST 写入 `backup/` 目录，命名为 `<源库名>_YYYYMMDD.db`；目录不存在时 MUST 自动创建。

#### Scenario: 首次备份

- **WHEN** `backup/` 目录不存在时执行备份
- **THEN** 目录被自动创建，并生成符合命名规则的备份文件

#### Scenario: 同日重复备份

- **WHEN** 同一天内重复执行备份
- **THEN** 覆盖同日期的备份文件，不产生多个同名变体

### Requirement: 备份必须是一致性快照

备份 MUST 使用数据库的在线备份能力生成一致快照，MUST NOT 以直接拷贝文件的方式读取可能正在写入的数据库。

#### Scenario: 备份期间有写入

- **WHEN** 备份执行期间其他进程正在写入业务数据库
- **THEN** 生成的备份文件可正常打开，且不包含写了一半的事务

### Requirement: 备份文件必须原子生成

备份 MUST 先写入临时文件，完成后再替换为目标文件；中断时 MUST NOT 在目标位置留下不完整的备份文件。

#### Scenario: 备份过程被中断

- **WHEN** 备份写入过程中进程被终止
- **THEN** 目标文件名下不存在半成品文件，残留的临时文件可被识别并清理

### Requirement: 备份完成后必须做完整性自检

备份完成后 MUST 对备份文件执行完整性检查；检查不通过 MUST 使该次执行失败并进入失败处理流程。

#### Scenario: 备份文件损坏

- **WHEN** 备份文件的完整性检查未返回成功结果
- **THEN** 该次备份执行失败，并按该任务注册的 catchup 属性与重试告警策略处理

#### Scenario: 备份成功

- **WHEN** 备份文件通过完整性检查
- **THEN** 该次执行成功，并在日志中记录备份路径与检查结果
